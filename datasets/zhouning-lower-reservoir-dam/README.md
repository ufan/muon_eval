# 坐标系与几何规则

## 1. 三套坐标

### 文档坐标 `doc_frame`

- `x_doc`：沿坝轴；东南端/⑩号坝段为 0，向西北/①号坝段递增，约 0–231 m。
- `y_doc`：垂直坝轴的水平轴；普通坝段上游面约为 0，向下游为正。
- `z_doc`：工程高程。
- 该坐标系按规格定义为左手系，只用于录入和解释工程资料。

### 模型坐标 `model_frame`

- `X = y_doc`：指向下游，方位约 47°。
- `Y = x_doc`：指向西北/左岸，方位约 317°。
- `Z = z_doc - 198`：向上，高程基准为▽198 m。
- 这是程序、导出方案和未来 Geant4 接口的右手坐标系。

反变换：

```text
x_doc = Y
y_doc = X
z_doc = Z + 198
```

### Legacy Three.js 场景坐标

Three.js 使用 Y 轴竖直。当前转换函数 `P([x_doc,y_doc,z_doc])` 为：

```text
scene.x = 115.5 - x_doc
scene.y = z_doc - 198
scene.z = -y_doc
```

方向向量必须使用对应的方向转换函数，不得把点变换直接用于向量。

### 主应用 compiled 路径

v0.7 候选参考点仍来自显式 doc_frame sidecar，通过 Geometry IR 的点变换进入 model_frame；不额外加旧应用的 0.4 m 示例站点偏移。默认姿态是平台初始值，不冒充 sidecar 的部署建议。

GLB/BVH 位置、索引与射线均在 model_frame；编译视图仅作 Z-up → Y-up 旋转，即 `scene = (X, Z, -Y)`，无模型坐标平移或比例变化。方向只旋转，不接受高程偏移。场景使用与 BVH 相同的模型缓冲；显示隐藏或透明度不会改变材料分类、路径和积分。

legacy 的程序化裁剪、网格显示和目标反事实启发式不用于此路径。compiled 只加载已发布的冻结工况，不从连续水位滑条修改网格；源实体目标/显著度未提供。主应用 UI 用声明的 model_frame 标签，不将固定屏幕左右方向当作岸别事实。

## 2. 几何语义

`dam_spec.json` 中：

- `solids` 是正体积：坝体、墩墙、平台和其他混凝土实体；
- `voids` 是负体积：从实体中掏除的廊道、井、孔洞、溢流孔和泄槽；
- 实际材料判定是 `solidContains && !voidContains`；
- 基础面以下通常判定为岩体；上下游水域按水位和空间范围判定。

支持的主要类型：

- `extrusion_x`：二维 `profile_yz` 沿坝轴 X 范围拉伸；
- `box`：轴对齐箱体集合；
- `sweep_xz`：按 X–Z 路径扫掠的廊道；
- `chute`：按 Y–Z 底板折线定义的泄槽负体积。

## 3. 显示规则

- 坝体显示为正体积表面。
- 廊道、观察室和电梯井可以作为彩色内部辅助结构显示。
- 泄洪孔、底孔和泄槽负体积不得以填充实体显示。
- 水力空腔通过坝体 shader 裁剪，泄槽底板和侧壁另外生成可见内表面。
- `addVoids()` 只能显示 `/gallery|obs|elevator/` 类型的内部目标。
- 边沿线是辅助表达，不应制造并不存在的结构边界。

## 4. 计算规则

- 射线先与工程包围盒求交，再使用主网格 DDA 前进。
- 当前主网格边长为 5 m；材料变化附近自适应细分至约 0.5 m。
- 射线路径分别累计 `concrete`、`water`、`rock` 和 `air`。
- 水当量由路径长度与 `dam_spec.json` 材料密度计算。
- 目标结构长度和掩膜用于投影轮廓与反事实显著度估算。

## 5. 修改几何时的检查表

1. 先修改 `dam_spec.json`，不要先在渲染代码里硬编码尺寸。
2. 检查 schema、规格断言和 `unknowns`。
3. 检查普通坝段和特殊坝段表面是否连续。
4. 检查负体积是否真正从材料分类中扣除。
5. 检查视觉裁剪与 `voidContains()` 边界一致。
6. 抽查中心射线的混凝土长度和相交目标。
7. 检查投影轮廓是否与三维结构方向一致。
8. 对不确定尺寸保留 `grade`、`status`、`source` 和可选 `range`，不要伪造精度。
