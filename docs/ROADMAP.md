# 功能现状与路线图

## 已实现

### 模型与显示

- 参数化 LOD2 坝体和 10 个坝段；
- 基础面、坝顶、普通坝段与溢流相关实体；
- 廊道、观察室和电梯井辅助显示；
- 上游库水、下游尾水示意面和上游水位调节；
- 坝体透明度调节、图层开关、标准视角和自由观察；
- 泄洪/底孔/泄槽负体积不再作为填充体显示；
- 水力空腔 shader 裁剪及泄槽底板、侧壁补面。

### 设备与站点

- 五个默认候选站点；
- 新建、删除和编辑候选点；
- 坐标、方位角和仰角编辑，角度输入框与滑条同步；
- 灵敏面积、条宽、读出条数、层间距等设备几何配置；
- 探测效率、角分布、死区、角分辨率、系统误差和曝光时间配置；
- 浏览器本地保存设备和候选站点状态。

### 评估与投影

- 自适应 DDA 材料射线；
- 混凝土路径、柱密度、预计计数、加权透射率、主网格数和路径范围；
- 25×25 预览、65×65 最终投影；
- 预计计数、透射率和结构显著度模式；
- 目标结构轮廓和 ROI 显著度；
- 悬停投影像素联动三维粗射线、体素和相交结构球形标记；
- 三维通量热云；
- JSON 方案导出。

### 界面与部署

- 左右侧栏收起/显示且保持 WebGL 长宽比；
- 环境图层和候选列表局部折叠；
- 投影窗口拖动/折叠；
- 本机离线、局域网、Docker/Nginx 和静态站点托管部署。

## 下一阶段：扫描功能

评价目标应从“孤立站点绝对分数”转向“约束空间内的相对比较”。建议分步：

1. 定义扫描域：允许的站点空间、姿态范围、步长和工程约束。
2. 定义统一计算接口：输入站点、姿态、设备、规格，输出可序列化指标。
3. 实现单线程批量扫描与取消/进度。
4. 增加缓存和 Web Worker。
5. 以排名、Pareto 前沿和局部最优展示结果，而非单一绝对等级。
6. 支持从扫描结果创建候选点并回到精细投影验证。

建议比较维度：

- 目标结构覆盖率；
- 有效像素/方向数量；
- 总预计计数；
- 加权透射率；
- 目标 ROI 综合显著度；
- 对位置/姿态扰动的稳健性；
- 与已有站点的互补性；
- 工程可部署约束。

## 后续计划

- 完整保存/加载方案，包含 schema 版本和向后迁移；
- 多站点同时显示和选中状态管理；
- 多站点联合评价与冗余/互补分析；
- 扫描结果 CSV/JSON 导出；
- 连续扫描动画或视频导出；
- 自动生成评估方案报告；
- 轮廓提取优化，可评估 OpenCV.js，但应先明确输入掩膜和轮廓语义；
- 更可靠的坝顶、溢流通道和其他结构边沿显示；
- Geant4 或高精度输运结果的交叉校验。

## 已知问题与技术债务

- `dist/app.js` 集中了几何、物理、渲染、UI、缓存和存储。
- 视觉空腔裁剪与材料分类使用两套实现，容易不一致。
- 部分泄槽高程规则仍硬编码在 JavaScript 中。
- 缺少自动化测试和几何基准数据。
- 当前计数模型是快速近似，尚未完成系统性物理验证。
- 当前“站点评估”仅展示单点指标，没有扫描内排名或不确定性。
- 保存仅使用 `localStorage`，导出后没有导入。
- 多站点无法同时显示和联合计算。
- CSS 分散在三个文件并依赖覆盖顺序。
- HTML 和 `app.js` 大量依赖固定 DOM ID。
- 投影任务在主线程分批运行，规模扩大后仍会成为性能瓶颈。
- `site-v*.tar.gz` 是临时发布产物，不应留在仓库工作区。

## 不建议立即做

- 不先验证计算结果就全面改写为新框架；
- 不在扫描实现之前设计复杂插件体系；
- 不把快速估算包装成施工级或安全级结论；
- 不为尚未出现的多坝站场景建立过度抽象。
